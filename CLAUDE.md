# remote-control

## Changelog

- Keep `CHANGELOG.md` up to date. It follows
  [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/).
- Every change that users or developers notice gets an entry under
  `## [Unreleased]`, in the same commit as the change. Use the groups
  `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed` and `Security`, in that
  order, and only the ones that have entries.
- Write entries for people, not commit messages: say what changed and why it
  matters, not which files were edited.
- On a release, rename `[Unreleased]` to `[x.y.z] - YYYY-MM-DD`
  ([Semantic Versioning](https://semver.org/spec/v2.0.0.html), ISO date), add
  a new empty `[Unreleased]` section, and update the version links at the
  bottom once the repository has a remote.

## Markdown

- No standalone lines that contain only `---`.
