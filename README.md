# remote-control

`remote-control` is a firmware for the M5Stack M5Paper. It reads remote
control configurations from Home Assistant, displays them and allows the user
the trigger action.

## Setup

On its first start the device has no configuration yet. It opens its own
Wi-Fi network and shows its name, password and two QR codes on the screen.
Join the network with your phone, open the upload page, and upload a
configuration file with your Wi-Fi and Home Assistant details. The device
checks the file and restarts with it.

Once configured, the device shows the views of your Home Assistant dashboard
as remotes, built with Bubble Card. A status bar at the top shows Wi-Fi,
date and time, battery, and a gear button that restarts into setup mode. To
change the configuration, tap the gear, or hold the push button of the rocker
switch for 3 seconds while switching the device on.

See [docs/user/configuration.md](docs/user/configuration.md) for the file
format, the supported cards and how to use the remote.

## Building

The firmware is built with ESP-IDF. You don't need to install ESP-IDF
yourself: the Makefile downloads a pinned toolchain into `toolchain/` on the
first run and uses only that.

### Prerequisites

- macOS or Linux, in a directory whose path has no spaces
- `git`, `curl`, `make` and [`uv`](https://docs.astral.sh/uv/)
- About 2.5 GB of free disk space for `toolchain/`, and network access on the
  first run

### Build

```sh
make
```

The first run installs Python 3.12, ESP-IDF v5.5.6 and the ESP32 tools into
`toolchain/`, which takes a while. Later runs only build. The image ends up in
`build/remote-control.bin`.

### Targets

| Target | Effect |
| --- | --- |
| `make` / `make all` | Install the toolchain if needed, then build |
| `make toolchain` | Install the toolchain only |
| `make build` | Build the firmware |
| `make flash` | Flash the firmware to the device. The stored configuration is kept |
| `make erase` | Erase the whole flash, including the stored configuration |
| `make monitor` | Open the serial monitor (exit with `Ctrl-]`) |
| `make menuconfig` | Open the ESP-IDF configuration menu |
| `make reconfigure` | Re-run CMake, needed after adding a component under `components/` |
| `make test-host` | Build and run the unit tests on this computer |
| `make assets` | Regenerate icons, fonts and the time-zone table |
| `make clean` | Remove build output, keep the toolchain |
| `make distclean` | Remove build output, downloaded components and `toolchain/` |
| `make help` | List targets and variables |

`flash` and `monitor` detect the serial port. To choose one, set `PORT`:

```sh
make flash monitor PORT=/dev/cu.usbserial-0001
```

Board settings (target, flash size, PSRAM, partition table) live in
`sdkconfig.defaults`. The generated `sdkconfig` is not under version control,
and it is regenerated when `sdkconfig.defaults` changes, so changes made with
`make menuconfig` last only until then.

The partition table in `partitions.csv` changed with the setup mode. On a
device flashed before that, run `make erase` once before `make flash`.

### Icons, fonts and time zones

The firmware embeds Material Design Icons, Noto Sans fonts and a time-zone
table. They are generated by `tools/gen_assets.py` into
`components/assets/generated/`, which is under version control, so a normal
build does not need the generator.

To add an icon, add its name (for example `mdi:garage-open`) to
`assets/icons.txt` and run:

```sh
make assets
```

The script downloads its sources once at pinned versions into
`toolchain/assets-cache/`, checks them against fixed checksums, and installs
Pillow into `toolchain/assets-venv/`. It stops with an error if a name in
`assets/icons.txt` is not a Material Design Icon. A contact sheet of all
icons and font samples is written to `toolchain/assets-cache/preview.png`.
